# 地天盘

**地盘看地形，天盘看天气。走之前两样都要看。**

---

## 这是什么

把紫微斗数和梅花易数合成一套**决策校验流程**。

| 层 | 工具 | 回答什么 | 时间尺度 |
|---|---|---|---|
| 第一层 | 紫微本命盘 | 这个方向，在我的结构里成立吗？ | 一生 |
| 第二层 | 紫微大限 | 这个十年，是发力期还是打地基期？ | 十年 |
| 第三层 | 梅花起卦 | 眼下这一局，顺势还是逆势？ | 数日到数月 |

**必须说清楚**：紫微与梅花在历史上是两个独立传承，古人没有系统合并过。**这套是新造的，不是古籍，没有经过验证。**

它的价值不在"更准"，在**防一种特定错误**：

> 某个方向在命盘上根本不成立，但某一卦显示"大吉"——因为那一局确实有外力相助。只看卦会去做，做完长期还是崩。

---

## 什么时候用

**适用**：

- "这个 offer 该不该接"
- "这个合作方靠不靠得住"
- "这单生意要不要做"
- "现在要不要换赛道/换城市"
- 任何**有具体选项、有具体时间点**的决策

**不适用**：

- "我这辈子怎么样" → 用紫微单独看
- "帮我算一下今天运气" → 不动不占
- 已经知道答案，想找个说法 → 拒绝
- 用户的命盘还没建立 → 先走紫微建档流程

## 核心机制：三元映射

### 第一步：定位决策落在哪个宫

| 用户问的是 | 对应紫微宫位 | 对应梅花"用" |
|---|---|---|
| 事业、职位、晋升 | 官禄 | 所问之事 |
| 钱、投资、收入 | 财帛 | 所问之事 |
| 伴侣、婚姻、合作 | 夫妻 | 所问之事 |
| 房产、搬家、家宅 | 田宅 | 所问之事 |
| 子女、下属、项目成果 | 子女 | 所问之事 |
| 健康、身体 | 疾厄 | 所问之事 |
| 外出、异地、搬迁 | 迁移 | 所问之事 |
| 人际、圈层、合伙 | 交友 | 所问之事 |

**"体"永远是命宫**——不管问什么，自己这一方都是命宫。

### 第二步：查三层状态

**第一层：该宫在本命的结构**

从 `chart.json` 读取：

- 该宫主星、亮度（庙旺得利平不陷）
- 有无煞星（擎羊、陀罗、火星、铃星、地空、地劫）
- 有无化忌
- 该宫三方四正（对宫、财帛位、官禄位）

判定：

```
结构强：主星庙旺 + 有吉辅 + 无煞忌  → 成立
结构中：主星平稳 + 少量煞  → 可做，但要控制幅度
结构弱：主星落陷 或 有化忌 或 煞星多  → 不成立
```

**第二层：该宫在当前大限的位置**

查 `chart.fortune.decadal_list` 和当前大限：

- 当前大限命宫是否在该宫或三方？
- 该宫是否被大限四化照到（禄/权/科/忌）？

判定：

```
配合：大限命宫在此宫或三方，或得大限化禄/化科
未配合：大限命宫不在附近，也无大限吉化
受阻：该宫得大限化忌
```

**第三层：梅花起卦**

按梅花技能起卦，得出：

- 本卦、互卦、变卦
- 体卦（命宫方）、用卦（所问之事）
- 体用关系：用生体 / 体生用 / 比和 / 体克用 / 用克体

判定：

```
吉：用生体、比和、体克用
凶：体生用、用克体
```

### 第三步：查飞化关系（这是关键补充）

**这一步是地天盘的核心，纯梅花做不到。**

从 `chart.transformations.palace_flights` 查两个方向的飞化：

| 飞化方向 | 梅花对应 | 含义 |
|---|---|---|
| **该宫 → 命宫**，且为禄/科 | **用生体** | 这件事能反哺我 |
| **命宫 → 该宫**，且为忌 | **体生用** | 我要消耗去贴这件事 |
| **命宫 → 该宫**，且为禄 | 主动投入 | 我愿意投入，且投入有效 |
| **该宫 → 命宫**，且为忌 | 用克体 | 这件事会反噬我 |
| 双方互飞、无忌 | 比和 | 势均力敌 |
| **该宫自化忌** | 内耗 | 这事在它自己身上打转，我使不上力 |

**这一层能把梅花的"体用"落到具体机制上。** 比如"体生用"在梅花里只是一个方向判断，在这套里可以说清"是哪颗星、从哪个宫、化什么、落到哪"。

---

## 判定矩阵（最终结论）

三层状态组合，得出四种结论：

| 命盘层 | 大限层 | 卦象层 | 结论 | 怎么说 |
|---|---|---|---|---|
| 成立 | 配合 | 吉 | **可动** | 方向对、时机对、这一局也顺 |
| 成立 | 配合 | 凶 | **方向对，时机错** | 等，或换方式做同一件事 |
| 成立 | 未配合 | 吉 | **可动，但收着做** | 方向对，但这十年不是发力期 |
| **不成立** | 任意 | 吉 | **陷阱** | 最危险的一格，必须拦 |
| 不成立 | 任意 | 凶 | **明确否** | 方向错、时机也不对 |
| 成立 | 受阻 | 任意 | **先解决阻力** | 找出化忌落在哪，先处理它 |

**第四行是这套方法唯一不可替代的价值。** 其他行，单用紫微或单用梅花也能大致判断。

## 四条禁区（最重要）

### 1. 不能用卦去推翻命盘

命盘说官禄弱，就不要起卦问"我事业能不能做大"。**这是拿卦去推翻结构，必然得到自欺的答案。**

如果用户坚持要问，要先说明：这一卦只能回答"眼下这一局"，不能回答"我能不能突破结构"。

### 2. 不能因卦吉就突破命盘禁区

见判定矩阵第四行。**卦吉只说明这一局有势，不说明这条路走得通。**

这是本技能存在的首要理由。

### 3. 不能给紫微没算的精度

紫微这版可以查流月流日（`flow.cjs`），但只作窗口排序；梅花能出"三日""三月"的应期。两套算法不同源，**无法交叉验证，也不能相加**。

正确表述：**"梅花这一层指向 X 日前后"，不能说"命盘也支持这个时间"。**

### 4. 不能反向工程

知道结果后再起卦，等于自欺。起卦必须在知道结果之前，且要记录起卦时间。

## 验证机制

**每一卦都要能追溯，否则这套方法永远无法被证伪。**

每次输出后，追加一条记录：

```markdown
### 记录
- 起卦时间：______（精确到分钟）
- 起卦方式：______
- 所问原文：______（用户原话，不改写）
- 判定结论：______
- 实际结果：______（待填）
- 复盘：______（待填）
```

记录写入该人的档案目录，不写入共享技能目录：
```
命理档案/YYYY-MM-DD_姓名/divinations/YYYY-MM-DD_HHMM.md
```

**攒够 10 次后做一次命中率统计。** 命中率低于随机水平，说明这套方法无效，应当明确告知用户并考虑停用。

## 共同的表达规则

继承紫微技能的语言风格要求：

1. **先说人话，再给依据。** 每节开头一句白话结论。
2. **术语必须翻译。** 不翻译的术语堆砌视为不合格。
3. **映射到具体场景。** 不说"官禄宫逢煞"，说"这个 offer 进去会卡在审批环节"。
4. **章节顺序：白话 → 原文 → 校勘。**
5. **每节结尾给可执行动作。**
6. 古籍原文照录，不删不改，与解释分层。

继承紫微的红线：

- 不用绝对化词汇（必成、必败、一定）
- 不替用户做决定，只呈现代价与收益
- 不因卦象恐吓
- 不作医疗、法律、投资建议

## 本技能的诚实声明

1. **这是新造的方法，不是古籍。** 紫微与梅花各自有传承，但系统合并没有历史先例。
2. **三元映射是假设，不是定论。** "体卦=命宫""用卦=所问宫位"这个对应，逻辑上自洽，但没有经过大样本验证。
3. **验证机制是必须的，不是可选的。** 不记录、不复盘，这套东西就只是说法好听。
4. **如果实测命中率不高于随机，应当停用。** 这句话要写在这里，防止以后自己骗自己。
