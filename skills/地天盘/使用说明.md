# 地天盘 · 使用说明

> 这是一份"怎么用"的文档，不是原理文档。原理见同目录 `SKILL.md`。

---

## 一、一句话说清它是干什么的

**当你面前有一个具体的选择，不知道该不该做的时候，用它过三道关。**

三道关分别回答：

1. **这件事的方向，适合我吗？**（看紫微本命）
2. **现在这个十年，是发力的时候吗？**（看紫微大限）
3. **眼下这一局，顺势还是逆势？**（看梅花起卦）

三关都过，可动。有一关不过，要看是哪一关。

---

## 二、它不能干什么（先看这条）

| 你可能会问 | 该用哪个 |
|---|---|
| "我这辈子怎么样" | 只用紫微 |
| "我是什么样的人" | 只用紫微 |
| "帮我算算今天运气" | 都不该用（不动不占） |
| "这个 offer 该不该接" | **地天盘** ✅ |
| "这个合作方靠不靠得住" | **地天盘** ✅ |
| "这单生意要不要做" | **地天盘** ✅ |

**核心区别**：紫微看一生结构，地天盘看"眼下这一个决定"。

---

## 三、用之前要准备什么

### 必须有的

1. **这个人的紫微档案已经建好**，并且在项目里：
   ```
   命理档案/YYYY-MM-DD_姓名/versions/vNNNN/chart.json
   ```
   没建档？先走紫微流程（`ziwei-doushu` 技能），别跳步。

2. **时间来源的可靠性已经确认过。**
   如果这个人的出生时间来自家人回忆、误差较大，**必须先说清换盘风险**，再谈决策。这是硬要求。

### 必须问清的

起卦前，必须问用户三件事：

```
1. 具体要决定什么？（一句话，要能落到"做/不做"上）
2. 有几个选项？（不能只有一个选项，那不算决策）
3. 什么时候要决定？（有没有时间压力）
```

**问不清楚就不要起卦。** 「我该怎么办」这种问题，起出来的卦没法解。

## 四、三步操作

### 第 1 步：定位

按问题找对应的宫位。

| 问的是 | 宫位 |
|---|---|
| 事业、职位、晋升、跳槽 | **官禄** |
| 钱、投资、收入、报价 | **财帛** |
| 伴侣、婚姻、合作方 | **夫妻** |
| 房产、搬家、装修 | **田宅** |
| 子女、下属、项目成果 | **子女** |
| 身体、健康 | **疾厄** |
| 异地、外派、迁移 | **迁移** |
| 人际、圈层、合伙 | **交友** |

**记住一条**：不管问什么，"我"这一方永远是**命宫**。

### 第 2 步：查盘

读当前版本 `chart.json`，查三个东西：

**① 该宫的结构**

```bash
# 示例：查官禄宫
python3 -c "
import json
c=json.load(open('命理档案/YYYY-MM-DD_姓名/versions/vNNNN/chart.json'))
p=[x for x in c['natal']['palaces'] if x['name']=='官禄'][0]
print('主星:', [(s['name'],s.get('brightness'),s.get('mutagen')) for s in p['majorStars']])
print('辅星:', [(s['name']) for s in p['minorStars']])
print('三方:', c['surrounded_palaces']['官禄'])
"
```

判读规则：

| 情况 | 结论 |
|---|---|
| 主星庙旺 + 有吉辅 + 无煞忌 | **结构强** |
| 主星平稳 + 少量煞 | **结构中** |
| 主星落陷 或 有化忌 或 煞星多 | **结构弱** |

**② 大限位置**

查 `chart.fortune.current_decadal`，看当前十年落在哪个宫、是否覆盖到该宫或三方。

**③ 飞化**

查 `chart.transformations.palace_flights`，只看两个方向：

- 该宫 → 命宫（是禄/科？）
- 命宫 → 该宫（是禄/忌？）

**这一步是地天盘的关键，纯梅花做不到。**

### 第 3 步：起卦

用梅花技能起卦。三种常用方式：

```bash
# 数字起卦（用户报三个数）
printf "3 28 39\n" | python3 ".trae/skills/meihua-yishu/scripts/iching_divination.py" numbers

# 时间起卦（用当下时间）
python3 ".trae/skills/meihua-yishu/scripts/iching_divination.py" date

# 三枚金钱（随机）
python3 ".trae/skills/meihua-yishu/scripts/iching_divination.py" coin
```

**起卦时必须同时记录起卦时间，精确到分钟。** 这是后续验证的基础。

## 五、怎么读结论

三层的状态组合，得出六种结论：

| 命盘 | 大限 | 卦象 | 结论 | 人话 |
|---|---|---|---|---|
| 强 | 配合 | 吉 | **可动** | 方向对、时机对、这一局也顺 |
| 强 | 配合 | 凶 | **方向对，时机错** | 事能做，但不是现在 |
| 强 | 未配合 | 吉 | **可动，收着做** | 方向对，但这十年不是发力期 |
| **弱** | 任意 | **吉** | **陷阱** | ⚠️ 最危险的一格 |
| 弱 | 任意 | 凶 | **明确否** | 方向错，时机也不对 |
| 强 | 受阻 | 任意 | **先解决阻力** | 找出忌落在哪，先处理 |

### 第四行，是这套方法唯一不可替代的价值

举个例子：

**举例（虚构）：某人的迁移宫主星落陷，又见两煞**——结构上"外出谈事"就是短板。

某天他为"要不要去外地谈一个大单"起了一卦，**卦象大吉**（用生体）。

- 只看梅花：去，吉利。
- 看地天盘：**陷阱**。为什么？因为卦可能只反映"这一局有外力相助"，不反映"这条路长期对他成本极高"。这一单成了，长期还是耗。

**这就是为什么需要合并。** 单用任何一门，都会漏掉这一格。

## 六、完整示例

> 以下为**虚构示例**：盘面数值一律用占位符，不对应任何真实档案。

### 决策：要不要接一个外地的大项目（虚构）

#### 第一层 · 命盘结构

**结论：不成立**

**依据**：
- 宫位：迁移（示例干支）
- 主星：示例主星（**陷**）
- 煞忌：示例煞星 A、示例煞星 B
- 三方四正：命宫（示例）、福德（示例）、夫妻（空宫）

读法：**示例盘的迁移宫是全盘摩擦最集中的一宫。**口舌、质疑、说多错多；一颗煞主急，一颗煞主落空。

#### 第二层 · 大限

**结论：未配合**

**依据**：
- 当前大限：示例虚岁区间（示例年份区间），示例宫
- 与本决策宫位的关系：大限迁移与本命迁移不重叠
- 大限四化：示例星化忌落示例宫

读法：这十年重心在"成果、主导的事"，不在对外扩张。

#### 第三层 · 卦象

**起卦方式**：数字起卦（示例数字 3、28、39）
**本卦**：第21卦 噬嗑　**互卦**：第61卦 中孚　**变卦**：第35卦 晋
**体卦**：震☳木（命宫方）　**用卦**：离☲火（所问之事）
**体用关系**：体生用（木生火）——我要消耗去成事
**卦辞依据**：噬嗑"亨，利用狱"——需要明断、有摩擦

#### 飞化验证

| 方向 | 星 | 四化 | 对应梅花 | 含义 |
|---|---|---|---|---|
| 命宫（示例干）→ 迁移 | — | 无飞化 | — | 命宫不主动投向往外 |
| 迁移（示例干）→ 命宫 | 示例星 | **忌** | **用克体** | 外部环境反噬自我状态 |
| 迁移 → 官禄 | 示例星 | 忌 | — | 在外跑动会把压力堆到事业 |

#### 综合结论

**四象限判定：陷阱**

命盘层不成立，卦象层却是体生用（费力但能成）。

**两套结论是否一致：不一致。**

分歧在于：卦显示"这一局能推动"，命盘显示"这条路长期对我成本极高"。**按地天盘规则，以命盘为准，拦。**

#### 行动建议

1. **不接这个项目**，或改成"远程参与 + 不承担对外谈判"的形式
2. 如果必须接触，先把所有条件书面化，避免口头承诺
3. 找一个人替你出面谈（迁移短板，借人之力）

#### 这道判断的不确定项

- 出生时间来源与误差尚未完全确定，存在换盘风险
- 卦象只反映起卦时刻，不覆盖三个月后的变化
- "外地"的具体程度未明确（跨省 / 跨国，摩擦量级不同）

## 八、每次都要记录

**不记录，这套方法永远无法被证伪。**

存到该人档案下，不进共享目录：

```
命理档案/YYYY-MM-DD_姓名/divinations/YYYY-MM-DD_HHMM.md
```

记录内容：

```markdown
### 记录
- 起卦时间：______（精确到分钟）
- 起卦方式：______
- 所问原文：______（用户原话，不改写）
- 判定结论：______
- 实际结果：______（待填）
- 复盘：______（待填）
```

**攒够 10 次，做一次命中率统计。**

命中率不高于随机水平 → 明确告知用户，考虑停用。

## 九、六个常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用卦去推翻命盘 | 自欺 | 命盘说弱就是弱，卦只能回答"这一局" |
| 因卦吉就突破禁区 | **陷阱** | 按判定矩阵第四行处理 |
| 给紫微没算的精度 | 假精确 | 流日必须来自 `flow.cjs`；没查就不能说"命盘支持某日" |
| 知道答案后起卦 | 反向工程 | 起卦必须在知道结果之前 |
| 问题太模糊就起卦 | 卦无法解 | 先问清"要决定什么、几个选项" |
| 不记录不复盘 | 永远无法验证 | 每卦必记 |

## 十、常见问题

**Q：一个人只能起一卦吗？**
不是。但**同一个问题**不要反复起卦。反复起卦本质是在找"想要的那个答案"。换个问法可以，换到想要的结果为止不行。

**Q：卦凶但命盘强，怎么办？**
按矩阵第二行：**方向对，时机错**。等，或者换方式做同一件事。

**Q：命盘弱但用户坚持要做？**
照实说结论，**不替用户做决定**。把"如果做，代价是什么"讲清楚，决策权归用户。

**Q：能不能不建档直接用？**
不能。没有命盘就没有前两层，那就只剩梅花，不是地天盘。

**Q：时间有换盘风险怎么办？**
先说明风险，再谈决策。**如果用户确认要按当前版本走，报告里必须写明"此结论建立在 XX 时辰的假设上"。**

**Q：紫微和梅花的结论冲突，信哪个？**
**信命盘。** 这是这套方法的设计原则——卦是"这一局"，命盘是"这条路"。

## 十一、边界声明

1. **这是新造的方法，不是古籍。** 紫微与梅花各自有传承，但系统合并没有历史先例。
2. **三元映射是假设，不是定论。** "体卦=命宫""用卦=所问宫位"这个对应，逻辑自洽，但没有大样本验证。
3. **它不预测必然发生的事。** 只提供结构倾向和可核对的判断依据。
4. **不替代医疗、法律、投资建议。**
5. **如果实测命中率不高于随机，应当停用。** 这句话写在这里，防止以后自己骗自己。
