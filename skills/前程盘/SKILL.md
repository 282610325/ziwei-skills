# 前程盘：方向、节奏、窗口

**一句话：这个技能不预测你会当多大官、赚多少钱。它只回答三件事——哪类事在你结构里成立、什么时候是发力期、眼下这三年该推还是该守。**

## 〇、与另外三个技能的分工

| 用户手上的问题 | 用哪个 |
|---|---|
| "我这辈子/这几年该往哪走""前程如何" | **前程盘** |
| "这个 offer 接不接""这单生意做不做" | 地天盘 |
| "这件事眼下成不成""什么时候有结果" | 梅花易数 |
| "哪个月适合动" | 前程盘（流月模块，仅在时辰确定时可用） |
| "我是什么样的人""十二宫逐宫详批" | ziwei-doushu 完整报告 |

**关键区别**：地天盘要求先有一个具体选项；前程盘不需要选项，它负责**产出选项**。所以通常是前程盘先跑，跑出来的"可行域"再交给地天盘做单点校验。

**分工的硬边界**：前程盘只做结构和节奏，不做单事件判定。任何"这个月会不会有消息""这次面试过不过"的问题，一律退回梅花或地天盘。

## 一、前置条件

### 必须已有

1. 该人档案已建档且为当前版本：
   `命理档案/YYYY-MM-DD_姓名/versions/vNNNN/chart.json`
2. 时间来源可靠性已核实。

### 时间不确定性：跨时辰就停

输入时间的不确定范围如果跨了时辰边界，**不出前程结论**。先让用户补时间，或用逐候选比较的明确指令。

例：09:30 ±30 分钟，范围 09:00–10:00 全在巳时 → 可以做，但报告里必须写明"若实际早于 09:00 则为辰时，本报告全部作废"。

### 不重复建档流程

建档、修订、排盘、封存一律走 `ziwei-doushu` 的脚本，本技能不另造一套。

### 身份隔离（强制）

本次允许进入上下文的只有：当前人的当前版本 `chart.json`、已确认输入、指定分析日期。档案名、生日、路径仅用于确认归属。

- 不得调用其他人的档案、经历、旧结论作依据
- 不得把上一人的可行域或大限判定沿用过来
- 同一份报告里出现两个以上人的宫位数据、或结论与 chart.json 对不上 → **立即停止，作废草稿，重新取数**
- 修改出生资料后必须用新版本重跑，旧版报告不得混用

发现混淆时不要边猜边改，重来一遍更快。

### 失败处理

以下情况一律停止，不手算、不绕过、不假装成功：

- `chart.json` 缺失、不是当前版本、或哈希与验收记录不符
- `qiancheng.py` 报错或输出为空
- 时间范围跨时辰且用户未确认按哪个时辰走
- 用户要求预测具体职位、收入、公司、事件

停止时说明缺哪一项、需要用户补什么。**禁止用语言模型手工安星或凭记忆补数据。**

### 首条回复（直接给，不弹窗）

档案已存在时，不要问"要不要新建"，直接：

```text
用【姓名 / 版本 vNNNN】（出生 YYYY-MM-DD HH:MM，时间来源与误差）
默认按"事业前程"输出：官禄为主，财帛、迁移为辅，田宅、福德、命宫作约束。
若你要的是"整体走向"而不是"事业线"，说一声，我调整六宫权重。
```

时间有误差时，紧跟一句风险说明。**不要在没确认时间可靠性的情况下开始推演。**

## 二、三轴方法

| 轴 | 用什么算 | 回答 | 时间尺度 |
|---|---|---|---|
| 第一轴 可行域 | 本命六宫 | 哪类事在我结构里成立 | 一生 |
| 第二轴 节奏 | 大限序列 | 这十年是发力、铺路、转型还是收缩 | 十年 |
| 第三轴 窗口 | 流年 | 这一年该推、该守还是该防 | 一年 |

三轴必须分开写，**禁止合成一句话**。合成就是把趋势说成事件，是这套方法最容易犯的错。

第四轴（可选）：**流月/流日窗口**。默认关闭，只在用户明确问"哪个月/哪天"且出生时辰确定时启用，规则见第五节末尾。

## 三、第一轴：前程六宫与判定

### 六宫权重

| 宫 | 回答什么 | 权重 |
|---|---|---|
| 官禄 | 做什么类型的活 | 主 |
| 财帛 | 怎么换成钱、现金能不能留 | 主 |
| 迁移 | 在哪做、对外与异地行不行 | 主 |
| 田宅 | 资产能不能沉淀、退路在哪 | 辅 |
| 福德 | 心力能撑多久、抗不抗长期高压 | 辅 |
| 命宫 | 本人驱动力上限、要不要外部约束 | 辅 |

**这个六宫分组是本技能的操作化定义，不是古籍原文。** 传统没有"前程六宫"这个说法。使用时不得说成古法。

### 单宫判定

判之前先固定三个口径，避免每份报告各说各话：

| 类别 | 包含 | 是否计入 |
|---|---|---|
| 吉辅星 | 左辅、右弼、文昌、文曲、天魁、天钺、禄存 | 计入"有吉辅" |
| 煞星 | 擎羊、陀罗、火星、铃星、地空、地劫 | 计入"有煞" |
| 吉化 | 化禄、化权、化科 | 计入"得吉化"，**但不等于吉辅** |

```text
强：主星庙旺 + 有吉辅 + 无煞忌
中：主星平稳，或有一煞/一忌但得吉化
弱：主星落陷，或坐化忌，或煞星≥2，或空宫且借宫不力
```

双主星亮度不一致时，以**差的那颗**定档，不得只挑好的那颗说。

空宫必须写"借对宫 X 星照"，不得当作"无此宫"或"没命格"。

### 三方四正：本宫为主，三方为辅

```text
- 本宫弱、但三方四正得庙旺或吉化 → 上调一档（弱→中），必须写明借力来自哪一宫
- 本宫强、但三方四正煞忌≥2 → 下调一档（强→中）
- 不得仅凭三方吉化把落陷本宫判为强
- 空宫借照与三方借力要分开写，不能混成一句
```

判定写成一行可核对的格式：`本宫 X（强/中/弱）＋ 三方 Y → 最终 Z`。

### 组合矩阵：结构决定路径形态

| 官禄 | 财帛 | 迁移 | 结构结论 | 对应路径形态 |
|---|---|---|---|---|
| 强 | 强 | 强 | 可行域宽 | 可主动扩张、接大盘、带团队 |
| 强 | 强 | 弱 | 坐着的活强，跑着的活弱 | 做交付/专业/后台，不做对外拿单 |
| 强 | 弱 | 中 | 事能做成，钱留不住 | 拿权拿名，钱走分成或固定，不押本金 |
| 弱 | 强 | 中 | 不适合当主帅 | 挂靠强平台，做分成型角色 |
| 弱 | 弱 | 强 | 靠自己不行，靠外部可以 | 借平台、借人、借渠道，别自己搭盘子 |
| 弱 | 弱 | 弱 | 三条主路都窄 | 守成，只修一项，不扩张 |

矩阵未列出的组合（共 27 种），按 **官禄 → 财帛 → 迁移** 的顺序取最弱一环作为结论，并写明取这一环的理由，不得含糊带过。

**三条附加约束（必须落到结论里）：**

- **田宅强** → 资产沉淀是退路，可以承受较长回收周期
- **福德弱** → 不做长周期高压项目，撑不到兑现就先垮
- **命宫弱**（主星平/陷、无辅）→ 必须给自己加外部约束（合伙人、固定客户、打卡式结构），否则靠自驱撑不住

### 四化分层：必须分开，禁止混成一句

四层全部来自 `chart.json`，每层单独标注：

| 层 | 取数位置 | 用在前程的哪里 |
|---|---|---|
| 本命四化 | `transformations.natal` | 决定这颗星是"带资源"还是"带卡点" |
| 本命宫干飞化 | `transformations.palace_flights` | 解释"为什么结构看着行，实际拿不到" |
| 大限四化 | `transformations.decadal` | 定这十年的节奏档位 |
| 流年四化 | `transformations.yearly`（未来年按年干推） | 定这一年的推/守/防 |

**宫干飞化是前程盘的必查项，不是可选项。** 重点看三种：

- **某宫自化忌**（`self_mutagen: true` 且为忌）→ 内耗：这股力量在自己身上打转，外面的资源进不来
- **某宫自化权** → 想在宫内抓主导，但容易自己跟自己较劲
- **官禄 / 财帛 / 命宫 三个方向互飞** → 直接对应"投进去的力，回不回得来"

禁止把宫干飞化说成生年四化，也不把飞化一概断成吉凶——它只说明力的走向。

## 四、第二轴：大限档位

### 四档定义

```text
发力期：大限命宫落本命官禄/财帛/命宫，且大限禄或权落事业线，且无大限忌入官禄财帛
铺路期：大限命宫落本命田宅/福德/父母/兄弟，或吉化不落事业线
转型期：大限命宫落本命迁移/子女/夫妻，且见破军/七杀/贪狼/廉贞/天机等动星
收缩期：大限忌入本命官禄或财帛；或大限命宫落疾厄/交友且煞星重
```

**这四档是本技能的操作化定义，不是传统定论。** 判定时必须把用到的宫位、四化、落点写出来，让读者能自己核对。

### 必给完整序列

至少给 **三个大限**（当前 + 后两个），表格列：虚岁区间、公历年份区间、大限命宫、大限四化落点、档位。

- 不得只讲当前大限
- 不得把公历年份区间说成精确交接日
- 未进入首个大限时写"尚未进入首个大限"，不把童限当十年大限

## 五、第三轴：流年窗口

只算 **未来三年**（含当前年）。

每年必须写四项：

1. 流年命宫叠在本命哪一宫
2. 流年四化四条，各落在哪一宫
3. 与本命、大限的叠宫关系
4. 一句判定：**推 / 守 / 防**

**禁止**：不给月、日级窗口；不把流年吉化说成"某月发财"；不用未计算的数据补应期。

### 年份口径（必须先声明）

- 年界按**农历正月初一**（`yearDivide=normal`）；报告必须写明"目标是哪一个农历年"，不能只写公历数字
- 用户只给年份时，取该年 **7 月 1 日**为年内参考日，并声明"不覆盖春节前后两个流年"
- 分析日距春节在 30 天内时，必须同时标注前后两个农历年，不得只取一个
- 年龄一律用库的虚岁口径（`ageDivide=normal`），不与周岁混用

### 未起限者

尚未进入首个大限时（童限），**只做第一轴可行域，不做大限档位与流年窗口**。报告写"尚未进入首个大限"，不得把童限当十年大限，也不得对未成年人给"该往哪走"的路径建议。

### 可选：月日窗口（只在用户明确问"哪个月/哪天"时启用）

默认不出月日级结论。用户明确要求时，先跑引擎脚本：

```bash
node "/path/to/workspace/.trae/skills/ziwei-doushu/scripts/flow.cjs" \
  --chart "/…/versions/vNNNN/chart.json" --date YYYY-MM-DD --months 6
```

口径由库固定，不得自行改：

- 月界 = 农历初一，不是公历 1 号；闰月后半月按 `fixLeap` 顺延
- 日界 = 晚子时 23:00–23:59 按来日
- 流月命宫 = 流年地支逆数至生月宫，再从该宫顺数至生时，为正月宫，其后每月一宫
- 流日命宫 = 流月命宫起初一，顺数至当日

**六条硬约束：**

1. **出生时辰必须唯一确定，否则整层不可用。** 流月算法含生时，时辰错一位整盘偏移。误差范围跨时辰、或正好压在时辰交接点上，都不能出这一层。
2. **只排序，不断事。** 只写"这个月推进 / 收 / 避"，不写"这个月会签成"
3. **不得用流月推翻流年。** 流年判守，流月再好也只是小步试，不能升格成大动
4. **流日只用于择日粗筛。** 一次最多 3 个候选日，说明是"避开明显冲突日"，不是黄道吉日
5. **范围上限 6 个月**，不铺满全年，不跨大限做月级推演
6. **流时默认不输出。** 用户坚持要，才附上并标注"时辰级，误差最大"

判定表写法（每行必须注明用的是哪一层数据）：

| 农历月 | 流月命宫叠本命 | 流月四化落点 | 与大限/流年关系 | 判定 |
|---|---|---|---|---|
| ___ | ___ | ___ | ___ | 推进 / 收 / 避 |

禁止把流月四化说成流年四化，也禁止把流日四化说成流月四化。

### 各节要求

**基本信息与口径**：开头三行固定写

```text
PERSON_ID: 工具生成的 person_id
VERSION: 当前版本数字
CHART_SHA256: chart.json 的 SHA256
```

正文列姓名/化名、原始历法日期、公历生日、钟表时间与来源误差、出生地点、时区与夏令时核实、校时量、分析日期、引擎版本。**时间临界风险单列，不藏在末尾。**

**一句话前程**：一句白话，不超过 40 字，说清"能做什么、卡在哪"。禁止形容词堆砌。

**底牌**：可行域列 3–5 条（能做的事），不可行域列 3–5 条（结构上不成立的事）。每条后跟盘面依据。

**前程六宫速览**：六行表，列宫位、主星与亮度、煞忌、强弱判定（强/中/弱）。这里的"强弱"是结构判定，不要和大限的"档位"混用同一个词。

**时间轴**：三个大限各一节，含档位、依据、该限的主要机会与主要风险。

**未来三年窗口**：三年表格，每年一行，列流年干支、流年命宫叠宫、四化落点、判定。

**路径选项与代价**：至少三条路径。每条必须写：

- 做什么（具体到岗位形态或商业模式）
- 命盘依据（哪宫哪星支撑）
- 收益
- 代价
- 什么情况下这条不成立

**只给两条路径视为不合格**：一条等于替用户做决定，必须给出对照。

**行动清单**：分 90 天 / 1 年 / 3 年三档，每档 2–3 条能当天开始做的事。

**不确定性与边界**：时间误差、流派限制、未计算层级、本技能自造部分。

### 交付形式

聊天里给压缩版，完整报告给链接：

```text
一句话前程（1 句）
→ 三个大限：档位各一行
→ 未来三年：推 / 守 / 防各一行
→ 三条路径：各一句代价
→ 明确写出时间误差与本报告作废条件
```

不把十二宫逐宫内容搬进聊天，也不只丢一个文件不解释。

## 七、红线

1. **不给职级、收入数字、公司规模、头衔等级。** 古籍里没有，现代命盘也推不出。
2. **不说"必成、必败、一定能、肯定"。** 只给结构倾向与代价。
3. **不用单一年份的吉化推十年。** 也不反过来用大限吉化保证某年顺利。
4. **不把大限当流年用。** 大限说"这十年有机会"，不等于"今年能落地"。
5. **不倒推履历。** 用户讲过的经历只用来核对盘面是否对得上，不得作为推演依据，更不得把已知结果包装成预测。
6. **不编造未计算的层级。** 流月流日只能引用 `flow.cjs` 的输出；没查询就写"没有"，不许凭印象补。
7. **不替用户做决定。** 只呈现代价与收益，决策权归用户。
8. **不因古籍断语恐吓。** 原文照录，解释层克制。
9. **不用性格形容词顶替路径判断。** "你有领导力"不是前程结论，"你适合在成熟体系里做统筹，不适合从零搭团队"才是。
10. **引用星性断语必须给出处。** 出处用 `ziwei-doushu/references/` 的文件名与行号；本地找不到就写"本地未找到充分条文"，不凭印象编造引文。
11. **古籍原文照录，不删不改。** 涉及强烈表述的段落也照录，只在解释层保持克制，不得以"敏感"为由删节。

## 八、语言风格

继承 `ziwei-doushu` 的强制要求：

1. **先说人话，再给依据。** 每节第一句必须是白话结论，出现在前 100 字内。
2. **术语必须翻译。** 首次出现即给现代含义。
3. **映射到具体场景。** 不说"官禄逢煞"，说"这个岗位会卡在审批环节"。
4. **章节顺序：白话 → 依据 → 校勘。** 不得把原文或校勘放开头。
5. **每节结尾给可执行动作。**
6. **短句优先，不堆排比。**

自检：一个不懂紫微的人读完，能不能说出"我该往哪走、什么时候动、代价是什么"。说不出就是术语堆砌，重写。

## 九、校验

### 第 1 步：取结构化摘要

不要凭记忆读盘，先跑摘要：

```bash
export SKILL="/path/to/workspace/.trae/skills/前程盘"

输出六宫强弱（含三方四正）、六宫宫干飞化、当前与后两个大限、未来三年流年四化。**后续所有引用必须来自这份摘要。**

需要月日级窗口时，再单独跑引擎：

  --chart "/…/chart.json" --date YYYY-MM-DD --months 6
```

摘要里的强弱与档位是粗判提示，报告可以用不同结论，但必须写出自己的判定依据，不能只抄提示。

### 第 2 步：写草稿后校验

```bash
python3 "$SKILL/scripts/qiancheng.py" check --chart "/…/chart.json" --report "/…/report.draft.md"
```

校验项：必填标题齐全、报告头含 PERSON_ID / VERSION / CHART_SHA256、三个大限年份能在 `decadal_list` 找到、六宫速览覆盖六宫、三条路径存在、绝对化词汇与收入数字告警。

未通过先改草稿，**不得声称已完成**。结构校验通过也不等于解释正确，还需人工核对：

- 每颗星、每条四化都能在 `chart.json` 找到
- 本命 / 宫干 / 大限 / 流年四层没有混写
- 时间误差与作废条件已写明

## 十、边界声明

1. **"前程六宫"是自造分组，不是古籍。** 传统只有十二宫，没有这个加权法。
2. **大限四档是操作化定义，不是定论。** 换一套流派权重可能不同。
3. **它不预测具体事件、职位、收入。** 只缩小可行域、标出节奏、排除自欺选项。
4. **不替代职业规划、医疗、法律、投资建议。**
5. **如果长期复盘命中率不高于"什么都不说"，应当停用。** 这句话写在这里，防止以后自己骗自己。
6. **流月流日的传统断法分歧最大。** 本技能只用它排序，不给事件结论；这一层要单独统计命中率，不高于随机就停用该层，不影响前两轴。
